# ST-Background-Reply — project context

## Goal
Decouple "waiting for a reply" from the current screen in SillyTavern: switch chats / reload / close the tab while a reply is generating, run several generations at once, and get a KakaoTalk-style corner notification (bot avatar + red unread badge) when a reply arrives. Third-party extension + optional server plugin; no SillyTavern core file is modified. Target: ST 1.19.0.

## Status
v1.2.0. v1.0.0/v1.1.0 worked on the user's real install. v1.2.0 lets the user keep chatting / run other commands while a /gen generates ("free input"). Server plugin unchanged, still 1.0.0 — no reinstall needed. v1.1.0 files are backed up in `backup/v1.1.0-20261024/`.

## Version history
- 1.0.0: background replies (switch/reload/concurrent), dock notifications, server plugin + installer.
- 1.1.0: `/gen` (quiet generation started by the /gen command) runs in the background as a "pipeline job" (src/pipeline.js); live preview card; badge aligned to .mes_text padding; generations with `quiet_prompt` but type normal (user's JS-Slash-Runner "/gen streaming override") are left to ST + notice; save-guard ignores first_message/command/extension MESSAGE_RECEIVED.
- 1.2.0: "free input" for /gen (setting `genFreeInput`, default on). Problem it fixes: while a /gen waited, ST kept `is_send_press` set AND the chat-input script lock (`isExecutingCommandsFromChatInput`, a module `let` in slash-commands.js that only its own `finally` resets) until the whole script finished, so Send/Enter/QR buttons did nothing — even in other chats after a switch. Now as soon as the /gen request is handed to the backend: ST's buttons are unlocked (unless another generation was already running when the /gen started — `busyBefore`), /gen's ephemeral `stop=` strings are flushed (request already built; `length=` restores itself via TempResponseLength's event hook), and the chat-input run is "released" (src/scriptrun.js) so ST sees it finished while its remaining commands keep running. The rest of the script still resumes only when the /gen's chat is open and ST is idle (existing `tryDeliver` rules); controller polls right after GENERATION_ENDED/STOPPED when a waiter exists. `/gen lock=on` or the setting off = old blocking behaviour; leaving the chat then also releases the run. The /gen command wrapper keeps the user's draft in #send_textarea when a released script reaches another /gen (generateCallback empties the input synchronously).

## Layout
- `index.js` — settings defaults (`extension_settings.bgReply`: enabled, genBackground, genFreeInput, livePreview, showRunning, sound, titleBadge, browserNotify, position, showDock), wires modules. `initCapture`, `initPipeline({freeInput})` and `initScriptRuns` run at module load so fetch / slash closures are wrapped early.
- `src/utils.js` — constants (plugin id `st-bg-reply`, marker key `extra.bg_reply`, supported URLs/types), `baseFetch`, `TAB_ID` (sessionStorage, survives reload of the same tab), cyrb53 `hash`, helpers.
- `src/jobs.js` — in-memory job registry + change listeners. Runtime-only fields: attached, detachRequested, stEof, stFailed, stSignal, rawText/rawBytes/decoder (plugin incremental read), raw (local), handling, notified, preview.
- `src/backend.js` — mode detection (`/ping`), `startJob` (plugin or local), `resumableBody` (on connection drop re-reads `/raw/:id?from=N&follow=1`), local mode (tee + IndexedDB via `store.js`, persisted every 1 s; running jobs of this tab become `interrupted` on reload), `refreshFromServer`, `readRaw`, `patchJob`, `claimJob`, `abortJob`, `removeJob`. Each job has `via` = plugin|local.
- `src/capture.js` — ST hooks. `GENERATION_STARTED` (type), `GENERATE_AFTER_DATA` arms a meta (TC: puts `__bgr` id into generate_data), `CHAT_COMPLETION_SETTINGS_READY` tags CC body (prompt identity check). Fetch wrapper strips `,"__bgr":"id"` and calls `startJob`; also counts `/api/chats/save` + `/api/chats/group/save` (`saveState`). `GENERATION_STOPPED` without detach = user Stop -> removeJob (aborts upstream). `MESSAGE_RECEIVED` (makeFirst): ST finished normally (`stFinishedNormally`: stEof, or no abort/failure — ST stops reading at `[DONE]`) -> consumed/removed; else marks ST's partial message and releases (detached). `isSaveExpected()` guards switches right after a reply.
- `src/apply.js` — chat key (`char|avatar|chatId`, `group|id|chatId`), fingerprints (`describeTarget`: anchor strict/loose for normal/regenerate, fp of swipes[0] for swipe, baseLen/baseHash for continue), markers on message extra + swipe_info extra, `placeJob` (append placeholder `...`, add swipe, mark continue target; adopts ST's unmarked partial when its text is a prefix), `alreadyInChat` dedupe, `processResult` (cleanUpMessage + REASONING regex), `fillJob` (writes swipe, emits MESSAGE_RECEIVED/CHARACTER_MESSAGE_RENDERED for the active swipe, saves), `discardPlaceholder`, `showLive` (DOM-only live text + badge with Stop).
- `src/controller.js` — `route(job)`: finished -> remove if delivered/dropped; apply if its chat is open (exclusive chain, claim first) else notify (preview + sound/browser notification once). Running & detached -> live preview tick (places placeholder, saves). Deleting a marked message/swipe = drop + abort. Polling 1.5 s busy / 3 s while bubbles / 7 s idle (20 s hidden). `openFromDock` scrolls to the reply.
- `src/pipeline.js` — /gen jobs. capture wraps the `/gen` command callback (sets a ticket; the next `GENERATION_STARTED` of type quiet within 5 s is the /gen's). The fetch wrapper hands tagged quiet requests to `startPipeline`: forces `stream: true` when ST streaming is on (not for json_schema/o1) for the live card, registers a waiter immediately and returns a Promise<Response> to ST. ST's quiet Generate stays awaiting it. On chat switch `suspendAttached()` = `setSendButtonState(false)` + `activateSendButtons()` (ST free, pipeline paused). `tryDeliver` (job finished per server/tab status AND its chat open AND, if suspended, ST idle) re-blocks ST (`setSendButtonState(true)` + `deactivateSendButtons()`) and resolves with the original JSON (non-forced) or a synthesized `{choices:[{message:{content}}]}` / `{choices:[{text}]}` (forced stream); errors -> 500 JSON; stop/discard -> AbortError (partial text is passed on for a plain stop). ST Stop while still attached rejects at once. Page reload = no waiter -> finished result goes to the inbox (`local.pipelineOrphan`). Live card `.bgr-gen-card` is a non-.mes child at the end of #chat.
- `src/scriptrun.js` — patches `SlashCommandClosure.prototype.execute`: for the root closure of a chat-input run (`this.abortController === commandsFromChatInputAbortController`, first closure seen with that controller) it returns `Promise.race([real, released])`. `releaseRun(ctrl)` resolves the race with an empty `SlashCommandClosureResult` (ST then clears its lock, progress bar, pause/stop buttons); progress callbacks are muted after release; the real run's later errors (SlashCommandExecutionError toast) and non-quiet aborts (warning toast) are reported here. `isReleasedRun(ctrl)` used by the /gen wrapper. capture's /gen wrapper records `args._abortController` + `lock` -> `genInfo` (+ `busyBefore = isGenerating()` at GENERATION_STARTED) -> `armed.gen` -> `startPipeline(job, path, init, gen)`; `job.scriptCtrl` kept for suspend.
- `src/nav.js` — capture-phase click interception on chat-switch selectors: detach (stopGeneration with detachRequested, wait release + ST's save + applyIdle) then replays the click. `openChat(key)`.
- `src/notify.js` — dock (`#bgr-dock`, top-positioned because mobile ST gives <html> a transform), bubbles grouped by chat, badge, running ring, preview tip for 4.5 s on arrival, title `(N)`, WebAudio ding, browser Notification.
- `src/panel.js` — drawer in `#extensions_settings2`: plugin status/version, toggles, job list (open/stop/delete), inbox for unplaceable replies (copy/append), install instructions with copyable paths.
- `server-plugin/index.mjs` — plugin `st-bg-reply`: `/ping`, `POST /start?id&url` (body = generation JSON + `__bgrMeta`; loopback to ST with cookie, x-csrf-token, authorization, host; 127.0.0.1/::1/localAddress; https with rejectUnauthorized false; does not abort on client close; streams to client + memory + `<id>.raw`; `delivered` when the response finished to a still-connected client), `GET /jobs` (marks stale running as interrupted, deletes >7 d), `GET /raw/:id?from&follow`, `POST /patch|/claim|/abort|/remove/:id`. Data: `data/<user>/bg-reply-jobs/`. `removed` flag prevents re-persisting deleted jobs; `exit()` marks running jobs interrupted.
- `installer/install.mjs` (+ `install-plugin.bat/.sh`, `uninstall-plugin.bat`) — finds ST root, copies plugin to `plugins/st-bg-reply` (backup to `backups/st-bg-reply-plugin/<ts>/`), sets `enableServerPlugins: true` in `config.yaml` / `config/config.yaml` (backup `config.yaml.bak-st-bg-reply-<ts>`), idempotent, `--uninstall`, `--st <path>`.

## Key ST 1.19 facts used
- Server aborts upstream when the client socket closes; `beforeunload` stops streaming; ST saves the streamed reply only at the end.
- `StreamingProcessor` writes to `chat[messageId]` without chat identity; switching right after a reply makes ST's pending `saveChatConditional` save into the new chat (we wait for the save).
- ST stops reading at `[DONE]`; `stopGeneration()` -> `isStreamFinished` true -> `onFinishStreaming` -> MESSAGE_RECEIVED -> save. `markUIGenStopped` (unblock) happens before MESSAGE_RECEIVED.
- Reasoning auto-parse runs on MESSAGE_RECEIVED if `extra.reasoning` is empty.
- Server plugins: `plugins/<id>/index.mjs`, `info{id,name,description}`, `init(router)`, routes after auth+CSRF+json parser (500 MB), `compression()` skipped via `Cache-Control: no-transform`.
