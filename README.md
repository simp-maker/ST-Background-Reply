# Background Reply (백그라운드 답장)

SillyTavern에서 **답장이 생성되는 동안에도 다른 채팅으로 이동하거나, 새로고침하거나, 창을 닫을 수 있게** 해 주는 확장입니다.
답장이 도착하면 화면 구석에 그 캐릭터의 동그란 프로필과 빨간 숫자 배지가 카톡 알림처럼 뜹니다.

- 전송 버튼은 그대로 씁니다. 따로 누를 버튼이나 확인할 보관함이 없습니다.
- 생성 중에 다른 캐릭터/채팅을 누르면 자동으로 백그라운드로 넘어가고 바로 이동합니다.
- 다른 채팅에서 또 보내면 여러 답장이 **동시에** 생성됩니다.
- 답장이 도착하면 알림 아이콘이 뜨고, 누르면 그 채팅으로 이동해서 답장 위치로 스크롤합니다.
- 그 채팅을 열 때 답장이 원래 자리에 자동으로 들어가 저장됩니다.
- 생성 중인 채팅으로 돌아가면 답장이 실시간으로 채워지는 게 보이고, 메시지 아래 **중지** 버튼으로 멈출 수 있습니다.
- **`/gen` 명령**도 생성 중에 다른 채팅으로 갈 수 있고, 같은 채팅에서 메시지를 보내거나 다른 명령을 실행할 수도 있습니다. 자세한 내용은 아래 [/gen 명령](#gen-명령) 항목을 보세요.

## 설치

### 1. 확장

이 폴더를 `SillyTavern/data/default-user/extensions/ST-Background-Reply` 에 넣고 SillyTavern 페이지를 새로고침합니다.
확장 설정(블록 아이콘) → **백그라운드 답장** 에서 상태를 확인할 수 있습니다.

확장만 있어도 채팅 이동·동시 생성·알림은 됩니다 (브라우저 모드). 이 모드에서는 새로고침하거나 탭을 닫으면, 생성 중이던 답장은 그때까지 받은 부분만 남습니다.

### 2. 서버 플러그인 (권장)

서버 플러그인이 있으면 **새로고침, 브라우저 종료, 폰 화면 꺼짐** 중에도 서버가 답장을 끝까지 받아 둡니다.

| 환경 | 방법 |
|---|---|
| Windows | 확장 폴더의 `install-plugin.bat` 더블클릭 |
| Mac / Linux / Termux | SillyTavern 폴더에서 `node data/default-user/extensions/ST-Background-Reply/installer/install.mjs` |

실행한 뒤 **SillyTavern을 재시작**하세요 (서버 창을 닫고 다시 실행). 확장 설정에 "서버 플러그인 연결됨"이 보이면 성공입니다.

설치 스크립트가 하는 일:

1. `server-plugin/` 을 `SillyTavern/plugins/st-bg-reply/` 로 복사합니다. 이미 있으면 `SillyTavern/backups/st-bg-reply-plugin/<시각>/` 에 백업한 뒤 교체합니다.
2. `config.yaml` 의 `enableServerPlugins` 를 `true` 로 바꿉니다. 바꾸기 전에 `config.yaml.bak-st-bg-reply-<시각>` 백업을 만듭니다.
3. SillyTavern 자체 파일은 건드리지 않습니다.

> 브라우저 확장은 서버의 파일이나 설정을 바꿀 수 없고 서버 재시작도 해야 해서, 확장 안의 버튼 한 번으로 켜는 건 불가능합니다. 대신 위 스크립트를 한 번만 실행하면 됩니다.

### 재설치가 필요한 경우

- **SillyTavern 업데이트** (`git pull`, `UpdateAndStart.bat`): 플러그인과 `config.yaml`이 그대로 남으므로 할 일 없음.
- **SillyTavern을 새로 설치했거나 폴더를 옮김 / 도커 컨테이너를 새로 만듦**: `install-plugin.bat` 를 다시 실행하고 재시작.
- **확장을 업데이트했는데 설정에 "플러그인 업데이트 필요"가 뜸**: 같은 스크립트를 다시 실행하고 재시작.

스크립트는 몇 번을 실행해도 안전합니다. 이미 최신이면 아무것도 바꾸지 않습니다.

### 제거

- 플러그인: `uninstall-plugin.bat` (또는 `node installer/install.mjs --uninstall`). 지우기 전에 백업을 남깁니다. `config.yaml`은 다른 플러그인을 위해 그대로 둡니다. 원래대로 돌리려면 `config.yaml.bak-st-bg-reply-*` 백업을 쓰면 됩니다.
- 확장: 확장 관리에서 삭제하거나 폴더를 지웁니다.

## /gen 명령

`/gen`의 결과는 채팅 메시지가 아니라 다음 명령(`/sendas`, QR 후처리 등)으로 넘어가는 값입니다. 그래서 일반 답장과는 다르게 처리합니다.

- **실시간 미리보기**: 생성 중에는 채팅 맨 아래에 `/gen` 미리보기 카드가 보입니다. 스트리밍 설정이 켜져 있으면 글자가 실시간으로 채워집니다. 카드의 **중지**로 멈추면, 받은 부분까지만 다음 단계로 넘어갑니다.
- **다른 채팅으로 이동**: 생성 중에 다른 채팅으로 가도 됩니다. 그 채팅에서 메시지를 보내도 됩니다.
- **돌아오면 이어서 진행**: `/gen` 다음 단계는 **원래 채팅으로 돌아왔을 때** 그 채팅에서 실행됩니다. 그래서 QR 패치의 접기 같은 후처리도 평소처럼 적용되고, 엉뚱한 채팅에 결과가 들어가지 않습니다.
- **완료 알림**: 끝나면 구석 알림에 `(/gen)`으로 뜨고, 누르면 그 채팅으로 가서 바로 이어집니다.
- **생성 중에도 입력 가능 (v1.2.0)**: `/gen`이 생성되는 동안에도 메시지를 보내거나 다른 슬래시 명령·QR을 실행할 수 있습니다. 채팅창에 직접 입력한 스크립트든 QR 버튼이든 마찬가지입니다.
  - `/gen` 뒤에 이어지는 명령(`/sendas` 등)은 `/gen` 결과가 나온 뒤, **그 채팅이 열려 있고 다른 답장 생성이 끝났을 때** 이어서 실행됩니다. 그래서 그 사이에 보낸 메시지가 있으면 결과는 그 뒤에 붙습니다.
  - 스크립트가 백그라운드로 넘어간 뒤에는 입력창 옆의 스크립트 일시정지/중지 버튼이 사라집니다. 멈추려면 미리보기 카드의 **중지**를 쓰세요. 이어지는 명령의 오류나 `/abort`는 평소처럼 알림으로 표시됩니다.
  - 이어지는 스크립트에 `/gen`이 또 있어도 입력 중인 글은 지워지지 않습니다.
  - 예전처럼 끝날 때까지 입력을 막고 싶으면 `/gen lock=on ...`으로 쓰거나, 확장 설정에서 **/gen 생성 중에도 메시지·다른 명령 보내기**를 끄세요. 끈 상태에서도 다른 채팅으로 이동하면 그 채팅에서는 입력할 수 있습니다.
- **새로고침했을 때**: 다음 단계를 이어갈 방법이 없어집니다. 이때는 결과 텍스트를 설정 패널의 **보관함**에 넣어 둡니다 (복사 / 채팅 끝에 추가).
- **대상**: 요약 같은 다른 확장의 자동 생성(quiet)은 대상이 아니라서 평소처럼 동작합니다.

주의할 점

- **'/gen 스트리밍' 사용자 스크립트**: JS-Slash-Runner로 `/gen`을 스트리밍하던 스크립트를 쓰고 있다면 **꺼 주세요.**
  - 그 스크립트를 거친 `/gen`은 실리가 임시 메시지로 스트리밍하는 방식이라, 안전하게 백그라운드로 돌릴 수 없습니다. 그래서 이 확장이 손대지 않고, 생성 중 이동도 막힙니다.
  - 켜져 있으면 설정 패널과 알림으로 안내합니다.
  - 미리보기 카드가 같은 역할을 합니다.

## 답장이 날아가지 않게 하는 장치

- **표식(marker)**: 답장이 들어갈 메시지나 스와이프에 작은 표식(`extra.bg_reply`)을 달아 둡니다. 그사이 메시지가 더 쌓여도 완성된 답장은 정확히 그 자리에 들어갑니다.
- **자리 찾기**: 새로고침 등으로 표식을 못 남긴 경우에는 보낸 시점의 직전 메시지(지문)를 기준으로 자리를 찾습니다. 그래도 못 찾으면 덮어쓰지 않고 설정 패널의 **보관함**에 보관합니다 (복사 / 채팅 끝에 추가).
- **덮어쓰기 금지**
  - 이어쓰기 도중 사용자가 메시지를 고쳤으면, 고친 내용은 그대로 두고 새 스와이프로 추가합니다.
  - SillyTavern이 이미 같은 답장을 저장했으면 다시 넣지 않습니다.
- **저장 순서 보호**
  - 채팅을 옮기기 전에 SillyTavern이 부분 답장을 저장할 때까지 기다립니다. 원래 SillyTavern에서는 생성 직후 너무 빨리 이동하면 저장이 엉뚱한 채팅으로 갈 수 있는데, 그것도 막습니다.
  - 답장을 넣는 동안에는 채팅 이동을 잠깐 미룹니다.
- **중복 적용 방지**: 여러 탭이나 기기에서 같은 채팅을 열어도 서버에서 한 번만 적용되도록 잠급니다.
- **연결이 잠깐 끊긴 경우**: 서버 플러그인 모드에서는 서버에 저장된 지점부터 이어 받아서, 화면의 스트리밍이 끊기지 않습니다.
- **사용자 의도 존중**
  - 정지 버튼 → 실제 요청도 취소합니다.
  - 생성 중인 자리의 메시지를 삭제하거나 재생성 → 그 답장은 버립니다.
- **서버가 재시작된 경우**: 받은 부분까지 넣고 알려 줍니다.

## 스트리밍 설정과의 호환

- **스트리밍 켬**: 평소와 똑같이 실시간으로 보입니다. 다른 채팅으로 가면 그 순간부터 백그라운드로 이어집니다.
- **스트리밍 끔**: 기다리는 중에 다른 채팅으로 갈 수 있고, 완성되면 알림이 뜹니다.
- 응답 해석과 후처리는 SillyTavern 함수를 그대로 씁니다. 그래서 정규식, 추론(thinking) 블록, 이름 정리 등은 평소 답장과 같게 처리됩니다.
  - 응답 해석: `getStreamingReply`, `extractMessageFromData`
  - 후처리: `cleanUpMessage`

## 지원 범위와 한계 (v1.2.0)

- **지원 API**: Chat Completion (OpenAI, Claude, Gemini, OpenRouter, 커스텀 등)과 Text Completion (ooba, KoboldCpp, llama.cpp 등).
  - KoboldAI Classic, NovelAI, Horde는 대상이 아니라서 평소처럼 동작합니다 (생성 중 이동 불가).
- **그룹 채팅**: 지금 답하고 있는 멤버의 답장만 백그라운드로 이어집니다. 남은 순서는 멈춥니다.
- **도구 호출(function calling)**: 답장이 도구 호출이면 백그라운드에서 이어서 처리할 수 없어 실패로 알립니다.
- **다른 확장의 반응 시점**: 다른 확장(TTS, 번역, 요약 등)의 "답장 받음" 처리는 그 채팅을 열어 답장이 들어갈 때 실행됩니다.
- **자동 이어쓰기**: 백그라운드에서 완성된 답장에는 적용되지 않습니다.
- **프롬프트 기준 시점**: 프롬프트는 보낸 순간의 채팅 기준입니다. 백그라운드 생성 중에 그 채팅에서 또 보내면, 새 요청에는 생성 중인 자리의 `...`(또는 받은 부분)이 들어갑니다.
- **브라우저 모드의 한계**: 브라우저 모드(플러그인 없음)는 그 탭에서만 기억합니다. 다른 기기나 브라우저에서는 보이지 않습니다.

## 테마 호환

"백그라운드에서 답장 생성 중" 표시는 메시지 본문(`.mes_text`)의 실제 시작 위치를 계산해서 맞춥니다. 본문에 안쪽 여백이나 테두리를 준 테마에서는 글자 시작 위치에 맞춰지고, 여백이 없는 테마에서는 그대로입니다.

## 데이터 위치

- 서버 플러그인: `SillyTavern/data/<사용자>/bg-reply-jobs/` (답장이 채팅에 들어가면 바로 지우고, 남은 것도 7일 뒤 자동 삭제)
- 브라우저 모드: 브라우저 IndexedDB `ST_BgReply`

## 보안 메모

- 서버 플러그인은 SillyTavern 자기 자신의 생성 주소 두 곳으로만 내부 요청을 보냅니다.
  - `/api/backends/chat-completions/generate`
  - `/api/backends/text-completions/generate`
- 요청을 보낸 사람의 로그인 쿠키, CSRF 토큰, 기본 인증 헤더를 그대로 붙이므로, 권한은 평소 요청과 같습니다.
- 작업 데이터는 사용자별 폴더에 저장됩니다.
